# DLNA 投屏 方案

结论：

- **「把 CDN 地址直接扔给电视」对 HLS 源基本必然失败**，不是难，是协议层对不上
- **唯一稳健的做法是「手机做本地代理」**：电视从手机拉，手机去 CDN 拉
- **零成本替代**：系统投屏（镜像），已经能用

---

## 0. DLNA 是什么，为什么不能直接投

DLNA 投屏（准确说是 UPnP AV 的 **DMC** 角色）做的事很简单：

```
我们（手机） --SSDP 发现--> 电视
我们 --SOAP SetAVTransportURI(URL)--> 电视
电视 ---------自己去拉 URL---------> 源
```

**控制器只传一个 URL，解码和拉流全是电视干的。** 所以问题变成：电视能不能拉这个 URL？

我们的流有三个特性，每一个都能把电视卡死：

| 特性 | 电视的表现 |
| --- | --- |
| **HLS / m3u8** | DLNA 标准里**没有 HLS**（只有 MPEG-TS / MP4 / MPEG-PS 等 profile），绝大多数电视不支持 |
| **必须带 `Referer`** | 电视不会带 → CDN 返回 **HTTP 200 + 16 字节「资源不存在!」**（实测过） |
| **AES-128 加密** | 电视更不会解密 |

所以「直接投 CDN 地址」这条路，对 HLS 源基本不可能成功。

---

## 1. 三条路径

### A. 只在 MP4 源上直接投（成本最低，覆盖面小）

代码里已经有 mp4 直链的识别（`internal/quality/episode.go` 的 `mp4TargetRE`，还会读 moov 拿分辨率），
说明确实有源给 MP4 直链。MP4 是 DLNA 电视支持最好的格式。

- 仍需解决 Referer（大概率还是得走代理）
- 只能覆盖少数源
- 成本：SSDP 发现 + SOAP 控制，约 1 天

### B. 手机做本地代理（唯一稳健方案）

```
电视 --LAN HTTP--> 手机内嵌服务 --CDN--> 源站
```

APK 里起一个小 HTTP 服务监听局域网，电视从 `http://<手机IP>:port/xxx` 拉流，代理负责：

- 加 `Referer` / `User-Agent`
- **AES-128 解密**（已实测 Java 能做，见 OFFLINE-DOWNLOAD.md §8）
- 把 HLS 分片按序拼成连续 TS 流（电视多数能播 MPEG-TS）

**关键优势**：电视和手机在同一 WiFi，走 **LAN 速度**，不经过 VPS 的 2.86 Mbps 上行。

**和下载功能共用 80% 的代码**：Referer 处理、AES 解密、内容校验（TS 0x47）、断点续传逻辑。
做完下载再做 DLNA，增量只有 SSDP 发现 + SOAP 控制 + 本地 HTTP 服务。

成本：SSDP（~150 行）+ SOAP（~100 行）+ 本地代理（~200 行）+ 真机兼容性调试，**2–3 天**。

风险：不同品牌电视对「TS over DLNA」的兼容性差异很大，**必须真机逐个试**，不能只测一台。

### C. 系统投屏（零开发，已经能用）

| 场景 | 怎么做 |
| --- | --- |
| Android 手机 | 系统「无线投屏 / 多屏互动」镜像整个屏幕 → APK 直接可用 |
| Chrome 桌面版 | 「投屏」投标签页 → 网页版直接可用 |
| Safari / iOS | `<video>` 自带 AirPlay 按钮（ArtPlayer 可能会隐藏，需要确认） |

缺点：这是**镜像**不是原生播放 —— 手机不能锁屏、画质取决于镜像编码、电视遥控器控制不了进度。

## 2. 一个 5 分钟就能验证的方法（先验证再开发）

不要先写代码。先用现成的 DLNA 控制器试你的电视：

1. 手机装 **BubbleUPnP** 或 **投屏助手**
2. 拿到一个真实 m3u8 地址（带 Referer 的那种）
3. 投过去，看电视报什么错

这一步能直接回答三个问题：
- 你的电视支不支持 HLS？
- 不带 Referer 会怎样？
- 电视对 TS 流的兼容性如何？

**如果电视连 HLS 都不支持（大概率），那路径 A 直接排除，只剩 B 和 C。**

---

## 3. DLNA 做不到的事

| 做不到 | 原因 |
| --- | --- |
| 字幕 | DLNA 协议层没有字幕轨道概念，除非把字幕烧进视频（要转码） |
| 弹幕 | 同上 |
| 一起看同步 | 电视端不受我们控制，无法注入时间轴纠正 |
| 精确 seek | 电视端的 seek 实现差异大，有的很卡 |

---

## 4. 替代方案：Chromecast 不推荐

Chromecast 支持 HLS，理论上更合适。但：

- 需要注册 Cast 应用 ID + 提供一个 receiver 页面
- **国内电视基本没有 Chromecast**
- 投入产出比差

---

## 5. 建议

先回答一个问题：**你要的是「电视上原生播放」，还是「在大屏上看」？**

- **只是大屏看** → 路径 C（系统投屏）已经能用，零成本，现在就能试
- **要电视遥控器控制、手机能锁屏** → 只有路径 B，2–3 天 + 真机调试

如果决定做 B，顺序是：**先做下载功能**（复用 Referer/解密/校验），再做 DLNA 增量部分。
反过来做会重复写一遍。

---

## 6. 需要拍板

1. 你的电视是什么品牌/型号？（决定兼容性预期）
2. 要「原生播放」还是「镜像就够」？
3. 如果做 B：手机作为代理必须常驻前台服务（通知栏有提示），能接受吗？
